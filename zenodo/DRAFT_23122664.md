## How this draft was created

`zenodo/new_version.py`, using `POST /api/records/<id>/versions`.

An earlier conclusion in this repository held that Zenodo could not create a new
version programmatically and that the web interface was the only route. **That
was wrong.** Both APIs live under `/api/` and the distinction is easy to miss
because every example online uses the legacy one:

| endpoint | result |
|---|---|
| `POST /api/deposit/depositions/<id>/actions/new_version` | 404 |
| `POST /api/deposit/depositions` with `metadata.conceptrecid` | 200, field **ignored**, draft lands on a different concept |
| **`POST /api/records/<id>/versions`** | **201, concept correctly linked** |

Use the third. `new_version.py` verifies the linkage before uploading anything and
aborts if it does not match.
